# 复刻流程

目标：重画出来的图和原图叠在一起相减几乎全黑，再把文字换成中文。靠的是量，不是看：先在原图上量出每个框的边、每段字的墨迹、每种颜色，再按原图坐标写 SVG。凭印象画，字号和线宽总会差一截，整张图就“不像”。

脚本都在本技能目录的 `scripts/` 下。

## 1. 准备原图

- 项目里已有的原图直接用。
- 外部的原图下载到临时目录，只在本地比对。项目里只提交自己画的 SVG 和导出的 WebP。
- 原图是 1280×720 的（Academy 智能体那几章），量出来的数值乘 1.5 换算到 1920 画布再写。
- 原图左下角的 ANTHROP\C 标志不画。

## 2. 量

写一个查询 JSON，跑 `node scripts/measure.mjs <原图> <查询.json>`。几种查询的写法见脚本开头的注释，常用的是：

- `px`：画布底色、每种色块的颜色（取在色块中间，避开文字）。
- `run` / `col`：横着、竖着穿过框边扫一遍，颜色变化的分段就是框的左右边、上下边和描边粗细；扫过箭头得到线宽；扫过虚线得到段长和间隔。
- `ink`：框出一段字，得到墨迹的左右上下。左右的中点就是 `text-anchor="middle"` 的 x。
- `top`：代码字、细线这种细笔画，用它取盒子里出现最多的颜色。

完成标准：每个框的四条边、每段字的墨迹盒、每种颜色都有数。

## 3. 认字体、反推字号

把每段字的墨迹宽 W、高 H 写进样本 JSON，跑 `node scripts/calib.mjs <样本.json>`。脚本用候选字体在 100px 下渲染同一串字，再按宽、按高各推一个字号：

- 两个字号相差在 5% 以内（输出写“吻合”），字体就认对了。字号取按宽推出的那个。
- 不吻合时换候选字体（Lora、Poppins、Roboto Mono，粗细、斜体都试），或者检查墨迹盒是不是把框线、箭头一起框进去了。
- 输出里的“基线 = 墨迹顶 + r × 字号”，就是这段字在 SVG 里该写的 y。

Academy 课件图里几乎只出现这几种：框名、便签、结论条用 Lora 常规体或粗体，连线说明用 Lora 斜体，标题、步骤条、消息表用 Poppins 600，消息表内容用 Poppins 斜体。

## 4. 写 SVG

- 从 `assets/template.svg` 开始，画布和原图同宽高比。坐标直接用原图像素；1280 宽的原图按第 1 节先乘 1.5。
- 样式先套 `academy.css` 的类。量出来的字号和类不同、差得又明显时（比如 53.5 对 54 不必管，64 对 60 要管），只在复刻时用行内 `style="font-size:64px"` 覆盖。
- 从后往前画：底色 → 生命线、容器 → 色块和框 → 线和箭头 → 字。

## 5. 叠图核对

```bash
node scripts/render.mjs <复刻>.svg --png /tmp/rep.png --no-webp
node scripts/compare.mjs <原图> /tmp/rep.png /tmp/cmp
```

打开 `/tmp/cmp-diff.png`：一样的地方是黑的。亮出来的完整轮廓说明位置偏了，按轮廓的方向挪；只亮半边说明粗细或字号差一点；整块发灰说明颜色不对。逐处改，再渲染、再叠。

完成标准：差值图只剩 1–2px 的细描边；`/tmp/cmp-stack.png` 上下并排看不出区别。

## 6. 汉化

- 叫法照目标文档已有的说法（比如文档里已经写成“您的服务器”“用户消息”“助手消息”，图里就照写）；代码名、消息类型名保留英文原样。
- 中文比英文宽：按每字 1em 重新估宽度，框放不下就换行，或者合并成一行（“Research / complete!” 可以变成一行“研究完成！”），框跟着改小，不缩字号。
- 中文一律正体；英文斜体说明换成中文后，渲染脚本会自动改正体。
- 再跑一次 `render.mjs`，照 SKILL.md 第 3 步看检查报告和预览。

完成标准：渲染检查没有 ERROR、没有“顶到框”的 WARN，预览里的版式还是原图的样子。
